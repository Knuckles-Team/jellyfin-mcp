# CONN-JELLYFIN-MCP — Requirements
| `CONN-JELLYFIN-MCP-R001` | **MediaBrowser token header.** The client in `jellyfin_mcp/api/api_client_base.py` sends the API key as `Authorization: MediaBrowser Token="<key>"` and never sends `X-Emby-Token`. The generator in `scripts/generate_code.py` emits the same header. Caller chain: the `jellyfin-mcp = scion_sdk.cli:serve` console script -> entry point `jellyfin_mcp:connector` (`jellyfin_mcp/__init__.py` line 12) -> `get_client` (`jellyfin_mcp/auth.py` line 21) -> `ApiBase.__init__` (`jellyfin_mcp/api/api_client_base.py` line 10), which sets the session header when a token is configured. Shape: `ApiBase` in `jellyfin_mcp/api/api_client_base.py` builds the header on its `requests` session; the generator line in `scripts/generate_code.py` line 62 mirrors it; no other file builds an auth header. | `tests/test_auth_header.py::test_token_sent_as_mediabrowser_authorization_header` must pass. |
| `CONN-JELLYFIN-MCP-R002` | **Env declarations match the code.** `.env.example`, `mcp_config.json` and the README must declare exactly the variables the code reads: no dead variable, no undocumented variable. Caller chain: the `jellyfin-mcp = scion_sdk.cli:serve` console script -> entry point `jellyfin_mcp:connector` (`jellyfin_mcp/__init__.py` line 12) -> `get_client` (`jellyfin_mcp/auth.py` line 21), which reads the JELLYFIN_* and delegation variables through `scion_sdk.config.setting`. Shape: the read surface is the `setting(...)` calls in `jellyfin_mcp/auth.py` and the SDK settings; `.env.example`, `mcp_config.json` and `README.md` are compared by `python -m scion_sdk.mcp.env_drift --check`, which `tests/test_env_declarations.py` runs. | `tests/test_env_declarations.py::test_env_declarations_match_the_code_read_surface` must pass. |
| `CONN-JELLYFIN-MCP-R003` | **One typed tool per operation.** The connector serves one typed tool per Jellyfin API operation (`jellyfin_<operation>`) and no `action=` router and no `params_json` passthrough tool. Caller chain: the `jellyfin-mcp = scion_sdk.cli:serve` console script -> entry point `jellyfin_mcp:connector` (`jellyfin_mcp/__init__.py`) -> `register_tool_surface` -> `register_kg_ingest_tools` (`jellyfin_mcp/mcp_server.py`), the only registrar, whose two tools take typed arguments. Shape: operation tools come from the `Api` client methods; `jellyfin_mcp/mcp_server.py` defines no condensed registrar. | `tests/test_coverage_gap_fillers.py::test_no_action_routed_or_json_passthrough_tools` must pass. |
| `CONN-JELLYFIN-MCP-R004` | **Item read works without a user.** `get_item` without `user_id` reads the item through the `ids` filter of `/Items`, because the server answers `GET /Items/{id}` without a user with HTTP 400. Caller chain: the `jellyfin-mcp = scion_sdk.cli:serve` console script -> entry point `jellyfin_mcp:connector` -> the `jellyfin_get_item` operation tool -> `LibraryClient.get_item` (`jellyfin_mcp/api/api_client_library.py`). Shape: one conditional in `get_item`; with a `user_id` the user-scoped route is unchanged. | `tests/test_coverage_gap_fillers.py::test_get_item_without_user_reads_through_the_ids_filter` must pass. |
| `CONN-JELLYFIN-MCP-R005` | **The whole surface is declared.** Every served tool is called by a tool-use contract step, linked to a prompt and a skill; the operator and four business-role prompts (media librarian, server administrator, playback coordinator, live TV manager) are complete agent definitions with data locations and roles. Caller chain: `jellyfin_mcp:connector` -> `load_surface` -> `jellyfin_mcp.connector_contracts`. Shape: `CONTRACTS`, `LINKS`, `LOCATIONS`, `ROLES`. | The `surface` gate is clean; every tool is called by a contract step. Test: `tests/test_surface_contracts.py::test_every_tool_is_called_by_a_contract_step`. |
